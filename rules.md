# Rules

- Do not remove existing comments unless the user explicitly asks for it.
- Keep changes focused on the requested task.
- Prefer minimal, local edits over broad refactors.
- Do not change unrelated files, APIs, or data models.
- Preserve existing naming, structure, and conventions unless a change is required.
- When adding new behavior, keep backward compatibility in mind.
- If a schema or contract changes, update the dependent code paths and tests together.
- Avoid cleanup work that is not directly needed for the task.
- Comment và ghi chú trong code phải viết tiếng Việt có dấu.
